# 筛选交互检查（my-app · 今日热搜）

## 一句话检查目标
它检查关键词筛选后列表是否**按标题过滤**、**无匹配时显示提示**、**清空后恢复全部**，并确认输入框有**可访问的标签**与**结果数量朗读**。

## 何时使用
- 用户要求验证 my-app 的关键词筛选是否正确。
- Day 12 任务：创建并调用本 Skill 完成一次筛选交互。

## 这个 Skill 检查了什么（用一句话说）
> 检查「按标题筛选」在三种情况下的行为是否正确，以及它是否对屏幕阅读器友好。

## 怎么调用（真实调用一次）
在项目根目录运行验证脚本，它会用 jsdom 加载真实的 my-app 并执行三种情况：

```
node my-app/tests/filter-verify.cjs
```

脚本退出码为 0 表示全部通过；任何一项失败会打印 FAIL 并以非零码退出。脚本的标准输出即为本次调用的「调用记录」。

## 三种情况（完成标准）
1. **有结果**：在搜索框输入能匹配到标题的关键词（如「初雪」），列表应只剩包含该关键词的条目，结果数量 > 0。
2. **无结果**：输入不会匹配任何标题的关键词（如「zzz不存在」），列表应显示空状态，文案包含「没有匹配「…」」且结果数量为 0。
3. **清空恢复**：把搜索框清空，列表应恢复显示全部条目（默认 5 条），结果数量回到总数。

## 可访问性检查（余力加练）
- 输入框 `#filterInput` 有可访问名称：要么 `aria-label`，要么存在 `<label for="filterInput">`。
- 结果数量区域 `#resultCount` 带 `aria-live="polite"`，筛选变化时可被屏幕阅读器播报。
- 无结果时以列表项（`.empty-box`）呈现提示，而非静默空白。

## 调用记录怎么留
每次调用后，把 `node my-app/tests/filter-verify.cjs` 的输出（含 PASS/FAIL 与三种情况结果）附在交付说明里，即「留有调用记录」。
