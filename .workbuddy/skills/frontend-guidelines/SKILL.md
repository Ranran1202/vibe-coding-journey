# 前端通用规范（可复用）

> 本规范抽离自真实项目中已被代码验证的写法，但**不绑定具体业务**。
> 新项目请先用约定的调色板/字体栈值（见「参考值」）与用户确认，再落地。

## 何时调用本 Skill
- 新建页面 / 组件、改 CSS、加交互之前，先对齐规范
- 修改前做检查清单、修改后做验证清单
- 用户问「前端怎么写才规范」「这个按钮/卡片该长什么样」

---

## 一、页面层级（结构）

- **移动优先、单列流式布局**，不要一上来做多栏桌面布局。
- 推荐结构顺序：
  1. 站点头部（标题 + 副标题）
  2. 主导航 / 筛选区（标签、搜索框）
  3. 工具条（操作按钮：刷新 / 收藏入口 / 主操作）
  4. 内容列表（每条 = 一张卡片）
  5. 页脚
  6. 详情用 **modal 覆盖层**，不要跳转新页（保持单页、上下文不丢）
- 内容容器**定宽居中**：`max-width` 约 640–760px（具体值按项目确认）。
- 一条内容 = 一个职责 = 一张卡片；别在一个卡片里塞多个独立功能。

## 二、颜色与字体

- **所有颜色用 CSS 变量集中在 `:root`，禁止散写十六进制字面量。**
  - 基础调色板变量：
    - `--bg` 页面底色
    - `--card` 卡片 / 浮层底色
    - `--text` 主文字
    - `--muted` 次级文字（说明、元信息）
    - `--accent` 品牌主色（最关键的操作 / 强调都用它）
    - `--border` 描边色
  - 新增颜色 → 先扩展这套变量，不要写死。
- **字体栈优先系统字体**（中文项目务必带中文字体）：
  `font-family: -apple-system, "Segoe UI", "Microsoft YaHei", sans-serif;`
- 文字层级：标题用 `--text` 加粗；说明 / 元信息用 `--muted` 且小一号。
- 主题：默认浅色；要做深色，另起一套变量集，**不要就地改值**。

## 三、卡片与按钮

**卡片**
- `background: var(--card)` + `1px solid var(--border)` + `border-radius: 10px` + 内边距。
- 列表项之间用 `margin` 分隔，不靠边框堆叠。

**按钮**（四类尺寸统一）
- 圆角 `8px`，`1px solid var(--border)`，默认 `min-height: 40px`。
- **移动端触控目标 ≥ 44px**（见移动端适配）。
- **状态必须齐全**（缺一不可）：
  - 默认
  - `:hover` → 描边或底色变主色
  - `:active` → 轻微下移 `transform: translateY(1px)`
  - `:focus-visible` → `outline: 2px solid var(--accent); outline-offset: 2px`（键盘可见）
  - `:disabled` → 降透明度 + `cursor: not-allowed`
- 主操作按钮用**主色填充**；次级用**描边按钮**；危险操作（删除 / 失败重试）用主色或深红。
- **操作反馈**：短暂动作给 toast；加载中给旋转图标 + 禁用态，不要只靠文字。

## 四、移动端适配

- **移动优先**：单位用 `rem` / `%`，间距走变量。
- **单一断点即可**：`@media (max-width: 480px)`。
  - toolbar 改竖排；按钮 / 输入框 `width: 100%`；触控目标升到 `44px`。
- `<meta name="viewport" content="width=device-width, initial-scale=1">` 必须有。
- **不依赖 hover 表达关键信息**（移动无 hover）：状态用颜色 / 文字 / 图标明确表达（如"已收藏"用填充色 + 文字）。
- 避免横向滚动：内容宽度 `100% - 内边距`，长文本 `line-height` 留白。

## 五、修改前检查（Checklist）

1. **读约定**：先看项目 `AGENTS.md` / 前端约定，确认本次改动在范围内、不越界。
2. **读变量**：读现有 CSS 的 `:root` 变量集；新增颜色 / 间距必须**扩展变量**，不写死字面量。
3. **确认归属**：结构在 HTML、样式在 CSS、逻辑在 JS —— 各司其职，不混写。
4. **不破坏已确认项**：已定下的类名、交互行为、主色，**不擅自改**，除非用户点头。
5. **交付方式**：优先给本地文件预览，不只用 GitHub 网页链接（网络抖动会误导"文件丢了"）。

## 六、修改后验证（Checklist）

1. **能渲染**：本地浏览器 / 预览面板打开，页面正常、控制台无报错。
2. **交互实测**：点击 / 筛选 / 弹窗 / 收藏等，各状态正确切换（含至少一种边界态：空结果、加载中、失败）。
3. **可访问性**：
   - 搜索框 / 表单有 `<label>` 或 `aria-label`；
   - 动态信息（结果数量等）用 `aria-live` 让屏幕阅读器朗读；
   - 焦点可见（`:focus-visible`）。
4. **移动端**：缩到 480px 宽，布局不破、按钮够大、无横向滚动。
5. **亲眼确认**：把"用户能亲眼看到"的结果交出去（截图 / 页面 / 命令输出），不口头说"完成了"。

## 参考值（来自某真实项目，新项目需与用户确认后替换）

- 调色板：`--bg:#f6f8fa --card:#fff --text:#24292f --muted:#57606a --accent:#d92b3a --border:#e1e4e8`
- 容器：`max-width: 720px; margin: 0 auto`
- 按钮圆角：8px；卡片圆角：10px；主控圆角：999px（标签胶囊）
- 断点：`@media (max-width: 480px)`

## 3 个成功标准（调用本 Skill 改完前端后的最低交付）

1. **规范合规**：新样式零硬编码颜色字面量（全部走 `:root` 变量）；按钮四态（hover / active / focus-visible / disabled）齐全。
2. **行为可验证**：用户能在浏览器里亲眼看到改动生效，且覆盖了**至少一种边界状态**（空结果 / 加载中 / 失败提示）。
3. **移动端不破**：`480px` 断点下布局正常、触控目标 ≥ 44px、无横向滚动。
