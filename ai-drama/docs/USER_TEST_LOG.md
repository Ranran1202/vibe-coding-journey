## 二、走查发现：同伴卡在哪一步？
**卡点：找不到「四种状态」在哪里看。**
- 旧版四态只能靠在网址后手动加 `?slow=1 / ?fail=1 / ?empty=1` 触发；默认打开是「瞬间加载成功」，所以普通测试者根本不知道还有「加载中 / 没有结果 / 请求失败」这几种状态。
- 最隐蔽的是 **「加载中」**：数据是本地内嵌、秒加载，正常双击打开永远看不到转圈——用户会觉得「这页面没有加载过程」。

**这一步我自己（开发者）为什么没发现？**
因为我验收时是用 jsdom「程序化地」把参数塞进去跑的，又用无头浏览器按指定 URL 截图。我全程**知道参数在哪儿**，于是默认用户也知道。我把验收标准定成了「测试通过 / 截图对」，而不是「一个没看过代码的人能不能自己发现这个功能」——这是典型的开发者盲区：验证了*实现*，没验证*可发现性*。

## 五、余力加练：手机宽度
**结论：真 390px 下版式正常，无需修复。**
- 用无头 Edge 直接 `--window-size=390,844` 截图时，右侧内容似乎被裁切——一度以为是窄屏溢出。
- 排查后确认是**假象**：Windows/Edge 存在最小窗口宽度（约 500px），实际以约 500px 版式布局、再裁到 390px，看起来像溢出。
- 改用**固定 390px 宽的 iframe**（`ai-drama-test-shots/mobile-frame.html`）强制真机版式后重截（`08-mobile-home.png`）：标题与文案正常换行、导航自动折到第二行且完整可见、按钮撑满整行（44px 触控）、设定表与卡片单列自适应——均正常。
- 复盘要点：**截图工具的“最小窗口宽度”会制造假的响应式问题**；验证窄屏要用固定宽容器/设备模拟，别信被裁过的整页截图。
